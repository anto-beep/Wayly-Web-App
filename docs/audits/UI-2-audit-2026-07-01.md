## 1. Font families, sizes, weights currently in use

### Sources of truth

| Where | Type | Value |
|---|---|---|
| `frontend/tailwind.config.js` (`fontFamily`) | heading | `"Fraunces", Georgia, "Times New Roman", serif` |
| ↑ | sans (body/UI) | `"Inter", -apple-system, "Segoe UI", Roboto, Helvetica Neue, Arial, sans-serif` |
| ↑ | mono (numbers) | `"IBM Plex Mono", ui-monospace, Menlo, monospace` |
| `frontend/public/index.html` line 34 | `<link>` | Google Fonts loads **`Inter:wght@600` only** — Fraunces + IBM Plex Mono are declared in Tailwind but **not preloaded**. Fonts hit fallback until CSS is parsed. |
| `frontend/src/index.css` | body font | Falls back to `-apple-system, BlinkMacSystemFont, ...` if Inter fails |
| `frontend/src/pages/Landing.jsx` and legal pages | inline | `Georgia,serif` used in one place as an intentional editorial serif (article-body pattern) |

**Findings**
- Tailwind config is already the single source of truth for the three families ✅
- **Bug**: the `<link>` in `index.html` only pulls Inter at 600 weight. Fraunces and IBM Plex Mono are used in Tailwind classes across every page but are never loaded. Result: heading serifs fall back to Georgia, numbers fall back to Menlo. Fix in Phase 1.
- No separate marketing vs app font config exists — good; there is nothing to consolidate.

## 4. Date and month rendering locations

### Utility
`frontend/src/lib/formatDate.js` — canonical DD/MM/YYYY formatter, plus `formatDateTime` (DD/MM/YYYY HH:mm).
✅ Exists. Used by ~40 call sites.

### Places that render dates NOT via the utility (bugs to fix in Phase 2/3)

| File | Line | Current format |
|---|---|---|
| `backend/scenario_engine/alerts.py` | 295 | `"a statement for {month_iso}"` — emits `"2026-05"` in the notification body. Must render as **`"May 2026"`**. |
| `frontend/src/pages/Reports.jsx` | 118 | `.toLocaleDateString("en-AU")` — coincidentally matches DD/MM/YYYY, but should go through the util. |
| `frontend/src/pages/statements/StatementAuditLog.jsx` | 27 | `new Date(a.at).toISOString().slice(0,10)` — renders `2026-06-15`. Must be DD/MM/YYYY. |
| `frontend/src/pages/AdviserPortal.jsx` | 191 | `.toLocaleString("en-AU", { month: "short", year: "numeric" })` — renders `Jun 2026`. Should render **`June 2026`** (full month per Rule 2.6). |
| `frontend/src/pages/tools/ClassificationCheck.jsx` | 68 | Hard-coded string `"May 2026 statement"` — literal string, OK. |
| `frontend/src/pages/CaregiverDashboard.jsx` | 245 | `dt.toDateString()` — renders `"Mon Jun 15 2026"`. Must go through util. |
| `backend/lib/pdf_reports.py` | 89 | `%Y-%m-%d` formatter in PDF footer. Should render DD/MM/YYYY. |
| `backend/lib/statement_lifecycle.py` | 44 | Emits `YYYY-MM` in audit trail message; must be `Month YYYY`. |

**No shared month-year formatter exists yet.** Recommend adding `formatMonthYear(iso)` to `lib/formatDate.js`.

### Currency utility

`frontend/src/lib/api.js` line 222 exports `formatMoney(n)` and a `formatMoneyDecimal(n, opts)`. Both use `Intl.NumberFormat('en-AU', {style:'currency', currency:'AUD'})` → renders `$1,234.00`.

All 8 tools live in `frontend/src/pages/tools/`. Current output structure:

| Tool | Opens with | Follows with | Notes |

| **StatementDecoderTool.jsx** | 3-line "You've decoded X" callout + free-use limit banner | Anomaly cards → line-item table → disclaimer | **Contains bug: strings "That was your free Statement Decoder use for today" and "Your free use for today" (Rule 4.4).** No plain-English summary section. |

5. No shared labels dictionary. Recommend creating `frontend/src/lib/toolLabels.js`.
