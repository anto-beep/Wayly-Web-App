## Section 13 · Delivery notes summary

Answers to the six questions the spec's Section 13 requires Emergent to answer:

1. **Original file retention pre-CPR-1?** Yes — GridFS + Mongo in ap-southeast-2 was already in use for AT-HM uploads (see A.1). No new storage backend needed.
2. **Which cross-tool read APIs pre-existed?** Only Family Coordinator (via the existing `get_household_for_participant()` helper). All 6 others will be built in the F.10 iteration.
3. **DOCX parsing library?** To be decided in the next iteration; `python-docx` is the intended default.
4. **OCR engine + region for images?** Reusing `pytesseract` (already in the environment); HEIC support to be added via `pillow-heif` in the next iteration. Runs in-container within the same ap-southeast-2 environment as the rest of the app.
5. **New program_reference entries added?** Yes — Statement of Rights (10 rights), National Quality Standards (7 revised standards), Aged Care Rules 2025 (3 sections). All new.
6. **QA lint auto-corrections during CI?** None so far. The build-time QA lint (§copy-qa) currently exits 0 across all new CPR-1 strings.
